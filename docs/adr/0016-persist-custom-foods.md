# ADR 0016: Локальное Хранение Созданных Продуктов

- Статус: принято
- Дата: 2026-09-24
- Область действия: пользовательский каталог продуктов

## Контекст

`/add-food/create` пока открывает заглушку. В отличие от временных данных
визуального прототипа, заполненный пользователем продукт не должен исчезать
после перезапуска. Макет `yam_create_product.html` не включает категорию для
принятого формата «категория · бренд», не определяет коэффициенты порций и
показывает неработающий сканер штрихкода.

## Решение

- Созданные продукты, их порции и флаг избранного сохраняются локально в
  Drift/SQLite. База является источником истины для «Моих блюд» и результатов
  поиска созданных продуктов. Существующие builtin fixtures и записи Дневника
  остаются presentation-прототипом в памяти до отдельного diary persistence
  slice; временные модели не становятся persisted domain entities.
- Для еды и порций используются публичные UUID v7, `createdAt`, `updatedAt`,
  устойчивый локальный `deviceId` и `deletedAt`. У базы есть версия схемы,
  тесты её создания и дальнейших миграций. Сохранение продукта и порций
  выполняется атомарно, а чтение/поиск остаются локальными.
- У формы есть обязательные название и категория (включая «Другое»),
  необязательные бренд и вводимый вручную штрихкод. Значения ккал и БЖУ
  обязательны для ввода, допускают ноль, не вычисляются автоматически друг
  из друга и не округляются при сохранении. Штрихкод хранится строкой, чтобы
  сохранить ведущие нули; сканер пока не показывается.
- Пищевая ценность указывается на `100 г`, `100 мл` или `1 порцию`.
  Для последнего варианта размер этой порции в г либо мл обязателен.
  Храним питательную ценность и базис в канонических единицах; исходный вид
  базиса доступен для корректного показа на экране. Дополнительные порции
  необязательны. Для каждой введённой пользователем штуки, ложки, стакана или
  именованной порции нужен положительный эквивалент в граммах либо мл того
  же продукта. Универсального `мл == г` нет.
- После сохранения возвращаемся к поиску, открываем «Мои блюда» и показываем
  новый продукт первым с кратким подтверждением. Выбранный приём пищи
  сохраняется; sheet и запись в Дневнике не открываются автоматически.
- Строки каталога, числовые/текстовые поля, кнопки, feedback и селекторы
  переиспользуют `lib/core/ui`; строки RU/EN берутся из generated l10n.

Этот ADR **заменяет** ограничение на отсутствие persistence в текущем
визуальном проходе из `agents/PROJECT_STATE.md` только для пользовательского
каталога. Он уточняет ADR 0007: его in-memory решения продолжают относиться
к дневным записям и демо-данным, но не к созданным продуктам. Для созданных
продуктов решение о session-only избранном из ADR 0012/0015 заменяется
локальным хранением. Требование обязательной порции из fixture в ADR 0015
не переносится на пользовательские продукты: без указанного коэффициента
в sheet доступен только базовый грамм или миллилитр.

## Последствия

Подключаются зависимости Drift/SQLite и генерация схемы, а не backend.
Текущий Flutter SDK закрепляет `meta` 1.17, поэтому используются совместимые
`drift`/`drift_dev` 2.31 и `drift_flutter` 0.2.4; обновление ветки Drift
требует отдельной проверки генератора при обновлении Flutter SDK. `uuid`
используется для UUID v7.
Изменение этой схемы в следующих slices проводится через проверенные
миграции. Сохранение custom food не означает, что история Дневника уже
персистентна; пользовательские записи Дневника остаются следующей задачей.
