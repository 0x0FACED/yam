# ADR 0041: Прилипание Переписки К Нижнему Краю

- Статус: принято
- Дата: 2026-11-06
- Основание: пользователь запросил автоскролл только пока находится внизу чата.

## Решение

- Новый чат начинает с включённым следованием за нижним краем.
- Пока список внизу, добавление сообщения, рост streaming-ответа и изменение
  геометрии переписки удерживают последний контент в поле зрения.
- Ручная прокрутка вверх отключает следование. Новые delta/сообщения и завершение
  ответа не меняют выбранную позицию. Возврат к низу включает следование снова.
  Допуск у нижней границы — 1 logical px для погрешности layout, не широкая
  «зона притягивания»: даже небольшое сознательное смещение вверх сохраняется.
- Программная доводка до конца не считается ручным скроллом. Обновления
  объединяются в один callback после layout; изменения scroll metrics учитывают
  ленивое построение сообщений и позднее изменение их размеров.
- Доводка без анимации: нет отдельного tween для каждого delta, а пользовательский
  скролл сразу отменяет ещё не выполненную доводку. Новый диалог сбрасывает режим.
- Это presentation-state экрана, без persisted-данных и изменения model/controller
  контрактов. Отправка своего сообщения из старой части диалога также не перехватывает
  скролл. Постоянное расположение composer из ADR 0040 не меняется.

## Проверка

- Native Flutter UI с управляемым streaming gateway: рост ответа при нахождении
  внизу, ручной wheel вверх на 8 px, дальнейшие delta, завершение ответа.
- Сохранение позиции вне нижней границы; возврат вниз и повторное прилипание.
- Несколько сообщений и поздние изменения lazy-list metrics; ошибок Flutter нет.
