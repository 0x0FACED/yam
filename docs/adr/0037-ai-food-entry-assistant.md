# ADR 0037: ИИ-Помощник Для Ввода Еды

- Статус: принято
- Дата: 2026-11-06
- Основание: пользователь одобрил отдельный экран помощника с текстом, голосом,
  фото и редактируемым черновиком перед записью.

## Решение

- Необязательный помощник ускоряет ввод еды; это не медицинский консультант,
  генератор диет или обязательный аккаунт YAM. Ручной local-first workflow,
  расчёты, просмотр истории и SQLite как источник истины не меняются.
- Этот ADR заменяет запрет на ИИ в текущем scope ADR 0001/0002 и blueprint
  только для описанного помощника. Остальные исключения MVP сохраняются.
- Отдельный task-screen открывается из Дневника и Настроек, сохраняет контекст
  локального дня/приёма пищи. Основная навигация остаётся трёхраздельной.
  Нового HTML-макета нет: используются canonical theme и существующие YAM
  формы, списки, feedback и nutrition patterns; без нового visual language.
- Два подключения: собственный ключ OpenAI и официальный Sign in with ChatGPT
  для eligible ChatGPT plans. Прямой Responses API, без собственного backend,
  Codex child process и недокументированных ChatGPT backend endpoints.
- OAuth: системный браузер, HTTP loopback, PKCE S256, state/nonce, проверка
  подписи/issuer/audience/expiry ID token, обновление и отзыв refresh token.
  Наличие входа не гарантирует entitlement: проверяются scopes и ошибки API.
- Доступные модели загружаются с API выбранного подключения. Для OAuth
  обязательны store:false/stream:true, контекст хранится на клиенте. История
  диалога и незаписанный черновик живут в сессии экрана; это явно сообщается.
- Ключи и токены хранятся в защищённом хранилище платформы, отдельно от SQLite,
  .yam backup, food-library JSON и логов. Режим подписки и API billing явно
  различаются; никакого общего ключа внутри приложения.
- Модель получает только запрос пользователя, приложенные изображения,
  контекст дня/приёма и результаты разрешённых инструментов. Чтение дня —
  только по запросу; весь каталог и история заранее не отправляются.
- Локальные инструменты: поиск и просмотр еды/порций, чтение выбранного дня,
  подготовка нового продукта и/или записей. Они не исполняют SQL, shell,
  произвольные URL или команды из названий/описаний. MCP не требуется.
- Модель только готовит черновик. Сохранение выполняется локальным кодом
  после одного явного подтверждения всего набора. Пользователь редактирует
  дату, приём, количество, удаляет строки и отдельно выбирает сохранение
  нового продукта в каталог. Чистое создание продукта также поддерживается.
- Количество порций переводится по коэффициентам конкретного продукта;
  миллилитры не равны граммам. Нутриенты каталога берутся из снимка, масштабирование
  выполняется существующим domain-кодом. Энергия нового своего продукта
  по-прежнему вычисляется из БЖУ согласно ADR 0017.
- Весь подтверждённый набор, включая выбранные новые продукты, записывается
  атомарно. Повторное подтверждение одного черновика не дублирует записи.
  Отмена/ошибка модели/сети/неполный stream не создают записей и не уничтожают ввод.
- Фото упаковки — чтение данных с проверкой человеком; фото тарелки — оценка
  с явными допущениями. Оценочный характер сохраняется в записи Дневника
  (schema v7, default false для старых данных), переносится backup и виден
  при дальнейшем просмотре/редактировании; каталог сам по себе не изменяется.
- Голос: короткая запись/распознавание, редактируемый текст, затем обычный
  сценарий. ChatGPT plan flow не поддерживает audio/transcription, поэтому
  используется системное распознавание там, где оно доступно, либо отдельная
  API-транскрипция с собственным ключом. Офлайн-распознавание не обещается;
  отсутствие разрешения/возможности явно показано, текст остаётся доступен.
- Медиа-зависимости, защищённое хранилище и JOSE допускаются для конкретных
  требований камеры/голоса, секретов и проверки OAuth; массового agent SDK нет.
- Нативное распознавание `speech_to_text 7.3.0` требует macOS 11.0: минимальная
  macOS повышается с 10.15 до 11.0; iOS остаётся 13.0. Это требование сборки
  зависимости, а не определение доступности русского/offline recognizer.
  `flutter_secure_storage 10.3.4` выбран вместо 11.x из-за несовместимого
  transitive win32 у существующего file_picker; общий major-upgrade не нужен.
- Android OS auto-backup/transfer отключён, чтобы не переносить credentials
  устройства; перенос пользовательских данных остаётся через явный `.yam`.
- Уточнение dev workflow (2026-11-07): для macOS privacy-сценариев приложение
  запускается как `.app` через LaunchServices или Xcode, затем подключается
  debugger. Прямой IDE → flutter run → executable может приписать TCC-запрос
  IDE и аварийно завершить YAM до Dart catch, хотя UsageDescription присутствует.
  `.vscode/launch.json`/`tasks.json` и `tool/run_macos.dart` задают безопасный
  запуск + attach; permissions/данные приложения и сам recognizer не подменяются.

## Проверка

- Поведение инструментов, единицы, ошибки и отсутствие записи до подтверждения.
- Атомарность/повторное подтверждение, миграция v6→v7 с сохранением истории,
  round-trip backup оценочных записей и совместимость старого backup.
- Реальный Responses stream: terminal completion, ошибки/обрывы, tool calls;
  OAuth callback/nonce/подпись/refresh на локальном HTTP сценарии без секретов.
- Flutter analyze, расчётные/persistence тесты и runtime-приёмка экрана.
  Настоящий провайдер требует пользовательского входа или API-ключа;
  локальная проверка протокола не выдаётся за успешный облачный вход.
