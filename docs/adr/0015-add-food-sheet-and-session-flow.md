# ADR 0015: Добавление Нескольких Продуктов И Управление Порциями

- Статус: принято
- Дата: 2026-09-24
- Область действия: presentation-прототип добавления еды

## Контекст

После каждой записи экран поиска закрывается и возвращает пользователя в
Дневник. Это мешает добавить несколько продуктов подряд. Sheet не позволяет
управлять избранным; смена единицы сбрасывает количество; кнопки шага меняют
его на произвольное для продукта число и слишком сильно закруглены.

## Решение

- После подтверждения закрывается только sheet; пользователь остаётся на
  поиске с запросом, фильтром и выбранным приёмом. Запись сразу появляется в
  Дневнике в памяти текущего запуска. На экране поиска показывается SnackBar с
  Undo; отмена убирает именно добавленную запись. Выбранный в sheet приём
  используется для следующих продуктов.
- Звезда в заголовке sheet добавляет/убирает продукт из Избранного; состояние
  обновляется в поиске и сохраняется до перезапуска. Краткий SnackBar при
  переключении виден поверх открытого sheet.
- CTA показывает действие и приём пищи, без повторения ккал: энергия и БЖУ уже
  представлены выше.
- Доступные для продукта единицы видны одной компактной строкой; выбранная
  выделяется, а эквивалент порции подписан. Смена единицы сохраняет реальное
  количество еды, не записывая округлённое представление обратно в расчёт.
- Одно нажатие `+`/`−` изменяет количество на 1 выбранную единицу. Удержание
  после короткой задержки повторяет шаг 1 всё быстрее до отпускания; повтор
  отменяется при уходе со страницы. Видимые поверхности управляющих кнопок
  используют геометрию contextual `+` из Дневника при доступной области
  нажатия не меньше 44 dp.
- У твёрдых продуктов прототипа есть граммы и порция с явным коэффициентом;
  штуки/ложки доступны только при заданном эквиваленте. У жидкостей остаются
  миллилитры, порции и стаканы: глобального приравнивания мл к граммам нет.
  Для яиц масса штуки явно задана в fixture. При будущем создании продукта
  пользователь определяет допустимые единицы и коэффициенты их пересчёта;
  Create Product в этом visual slice пока остаётся отдельной задачей.
- Новое поведение использует in-memory presentation state, без базы и нового
  доменного слоя.

Этот ADR **заменяет** в ADR 0007 пункт о возврате в Дневник сразу после
каждого добавления; сохранены предвыбор приёма, количественный sheet,
визуальная обратная связь и Undo. ADR 0012 о цельной строке продукта и
вкладках поиска остаётся в силе. Экранный HTML `yam_add_food.html` уступает
этому решению в местах единиц, CTA, избранного и геометрии stepper-кнопок.

## Последствия

Дневник и поиск должны синхронно видеть добавления, Recent и избранное внутри
запуска. Точность расчёта и преобразования единиц проверяются отдельными
прицельными тестами; полный UI suite не требуется при визуальных итерациях.
