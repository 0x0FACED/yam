# ADR 0026: Сохранение Категорий Пользовательских Продуктов

- Статус: принято
- Дата: 2026-10-23
- Область действия: backup, чтение каталога и редактирование сохранённого продукта

## Контекст

Экспорт действующей SQLite v4 отклоняет сохранённые продукты, категории которых
не входят в presentation enum. При этом persisted модель хранит категорию как
TEXT, а CustomFoodDraft/UserFoodRepository допускают текстовые категории.
База проходит SQLite integrity check: ошибочно дополнительное ограничение
backup-кодека, а не пользовательские записи. Те же `.values.byName()` в UI
мешают чтению и правке таких продуктов после восстановления.

## Решение

- Категория в backup и модели строки каталога — сохраняемый непустой текст,
  не закрытый UI enum. Стандартные категории остаются набором предустановок,
  их коды локализуются как раньше; прочие значения отображаются как данные
  без перевода, подмены на «Другое», удаления или нормализации.
- Форма правки добавляет текущую сохранённую категорию к вариантам выбора,
  если её нет в предустановках. Правка других полей не меняет категорию.
  Создание новых произвольных категорий и управление ими не добавляются.
- Экспорт и импорт сохраняют исходные категории активных и удалённых продуктов.
  Остальная проверка backup — типы, обязательные поля, конечные числа,
  единицы, связи, UUID, снимки и ограничения архива — сохраняется.
- Схема SQLite v4 и формат `.yam` v1 не меняются: поле категории уже текстовое.
  Исходные данные не переписываются ради возможности экспорта.
- Ошибка подготовки данных к экспорту получает отдельный RU/EN текст;
  сообщение «не резервная копия / файл повреждён» относится только к импорту.

Это уточняет ADR 0016 и 0024: presentation-предустановки не ограничивают
существующие сохранённые категории. Не вводит новую taxonomy или migration.

## Проверка

Синтетическая SQLite regression для нестандартных категорий и полного roundtrip,
без пользовательских данных в репозитории. Runtime на приватной диагностической
копии: экспорт и восстановление должны сохранить все шесть таблиц побайтно по
значениям полей. Отдельно проверяются отображение и правка категории, и отсутствие
импортного сообщения в ошибке экспорта. Результаты записываются в PROJECT_STATE
без содержимого пользовательской базы и приватных путей.
