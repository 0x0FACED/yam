# ADR 0038: Прокси Для Сетевых Запросов Приложения

- Статус: принято
- Дата: 2026-11-06
- Основание: пользователь запросил настраиваемый HTTPS/SOCKS5-прокси после
  подтверждённого отказа OpenAI `unsupported_country_region_territory` при обмене
  OAuth-кода из YAM; браузерный вход не задаёт маршрут запросам приложения.

## Решение

- В Настройках появляется отдельный task-screen «Прокси»: включение, протокол,
  host, port и необязательные username/password. HTTP-прокси поддерживает CONNECT
  к HTTPS-сервисам; HTTPS-прокси дополнительно шифрует соединение до самого
  прокси; SOCKS5 поддерживает отсутствие авторизации и username/password.
- Настройка относится ко всем HTTP-запросам, которыми владеет YAM: ChatGPT OAuth
  (обмен, discovery/JWKS, refresh/revoke), список моделей, Responses/SSE,
  API-транскрипция, Open Food Facts и GitHub updater, включая загрузку assets.
- Общая фабрика `HttpClient` находится в `lib/core/network` и явно передаётся
  существующим клиентам из app composition root. Глобальный `HttpOverrides`
  не применяется; тестовые/внедрённые клиенты остаются изолированными.
- Для HTTP/HTTPS используется CONNECT, для SOCKS5 — CONNECT с адресом назначения
  на стороне прокси. Имена удалённых сервисов при SOCKS5 не резолвятся локально.
  Проверка сертификатов целевого HTTPS-сервера и HTTPS-прокси сохраняется.
- Включённый прокси работает без direct fallback: ошибка соединения или
  авторизации не должна незаметно отправлять запрос в обход выбранного маршрута.
  Секреты прокси не попадают в заголовки целевого сервиса.
- Конфигурация, включая credentials, хранится одним отдельным per-device record
  в существующем platform secure storage. Не SQLite, `.yam`, food-library JSON,
  логи или обычный preferences-файл. macOS использует тот же legacy Keychain
  policy, что подключения помощника; новых зависимостей не требуется.
  Android использует отдельный namespace `yam_network_proxy` и
  `resetOnError:false`: ошибка расшифровки не должна удалять настройку и
  превращаться в «прокси выключен», в том числе через другой storage instance.
- Сохранение атомарно на уровне record: настройки начинают действовать только
  после успешной записи. Смена настроек закрывает прежние сетевые соединения,
  включая pooled connections; последующие запросы используют новый маршрут без
  перезапуска. Прерванный пользователем сменой маршрута запрос можно повторить.
- Чтение настроек завершается до первого исходящего соединения. Ошибка secure
  storage блокирует только сеть, а не локальный Дневник/каталог и историю.
  Включение/изменение прокси не запускает запросы само по себе.
  Отмена сетевого запроса доступна уже во время чтения secure storage: после
  отмены завершение чтения не должно запускать отложенное соединение.
- Отключение возвращает прямые запросы, сохраняя поля для повторного включения.
  Host/port/auth проверяются до сохранения включённого прокси; пароль не обрезается.
- Системный браузер OAuth, внешние URL и нативное speech recognition принадлежат
  ОС и не перенастраиваются этим экраном. Loopback callback остаётся локальным
  HTTP-сервером; браузер должен иметь собственный работающий сетевой маршрут.
- UI переиспользует canonical theme и YAM fields/select/buttons. Нового
  визуального направления нет; RU/EN и скрытый пароль обязательны.
- SOCKS5 username/password и Basic credentials через обычный HTTP-прокси не
  шифруются на участке до прокси; HTTPS-прокси шифрует этот участок. TLS целевого
  HTTPS-сервиса остаётся включённым во всех трёх вариантах.
- Настройка маршрута не обещает entitlement или доступность провайдера. Ошибки
  региона, плана и сервера не подавляются и не трактуются как успешный ответ.

## Проверка

- Реальные loopback HTTP CONNECT / TLS CONNECT / SOCKS5: запросы через туннель,
  optional auth, ошибки/обрывы/фрагментация и отсутствие direct fallback.
- SOCKS5 remote DNS, отказ неподходящим credentials, сохранение проверки TLS.
- Смена маршрута после pooled direct/proxy connection и отказ secure storage.
- Сохранение/повторное чтение настроек; ошибка записи не меняет активный маршрут.
- Native runtime формы, скрытый пароль, narrow/large-text scroll и применение
  настроек к реальному локальному сетевому сценарию. Облачная приёмка отдельно,
  только с пользовательским прокси и авторизацией; fixtures не заменяют её.
