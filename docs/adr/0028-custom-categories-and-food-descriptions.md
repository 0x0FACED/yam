# ADR 0028: Свои Категории, Описания И Действия Продуктов

- Статус: принято
- Дата: 2026-10-26
- Область действия: создание/правка UserFood, поиск, карточка добавления, backup

## Контекст

Пользователь хочет вводить собственные категории с подсказками, хранить у
продукта описание (например, ингредиенты и способ приготовления блюда) и
редактировать или удалять свой продукт непосредственно из любой выдачи поиска.
Сейчас категории ограничены селектором предустановок, описания нет, а меню
правки доступно только в «Моих блюдах».

## Решение

- Категория — обязательный свободный ввод с локальными подсказками по префиксу,
  как у бренда. Подсказки объединяют локализованные предустановки и категории
  активных UserFoods/RemoteFoods; не более пяти вариантов, без сети. Выбор
  подсказки необязателен. Предустановки сохраняют канонические коды, собственные
  категории остаются пользовательскими данными без перевода. Открытие и правка
  других полей не должны подменять существующую категорию.
- У своего продукта появляется необязательное многострочное текстовое описание.
  Оно вводится в общей форме создания/правки, сохраняется между запусками,
  допускает очистку и целиком доступно для чтения в карточке добавления продукта.
  Это заметка, а не отдельная сущность рецепта: ингредиенты не связываются с
  каталогом, расчёт КБЖУ не меняется, разметка не интерпретируется.
- SQLite обновляется аддитивно с v4 до v5: nullable TEXT `description` в
  `user_foods`. У старых продуктов описание отсутствует; существующие ID,
  метаданные, категории, порции и снимки Дневника сохраняются. В RemoteFoods
  и исторические Diary snapshots описание не добавляется.
- Новые `.yam`-копии используют `formatVersion: 2` и включают nullable
  `description` пользовательских продуктов, в том числе удалённых. Импорт
  поддерживает v1 без описания и v2; будущие версии отклоняются. Версия формата
  повышается, поскольку прежний валидатор проверяет точный состав полей:
  старое приложение должно отклонить новую копию, а не незаметно потерять заметки.
  Ограничения ZIP, проверка данных, атомарность и семантика «Заменить»/«Дополнить»
  ADR 0024 сохраняются.
- Меню «Изменить»/«Удалить» доступно у активных UserFoods в «Недавних», «Моих
  блюдах», «Избранном» и результатах текстового поиска. Возможность определяется
  происхождением продукта, не выбранной вкладкой. Встроенные и OFF-продукты
  не становятся редактируемыми. После правки сохраняются запрос и вкладка;
  удаление использует существующее подтверждение и soft delete. История
  Дневника не переписывается.

Этот ADR **заменяет** ограничение ADR 0026 на создание произвольных категорий,
ограничение ADR 0023 на доступ к правке только из «Моих блюд» и правило
ADR 0024 о единственной поддерживаемой версии backup v1. Остальные требования
этих ADR сохраняются.

## Проверка

Миграция v4→v5 и сохранность существующих данных; создание, изменение, очистка
и повторное чтение описания; перенос описания в v2 и чтение v1; подсказки без
удалённых продуктов и дубликатов; правка/удаление из поиска без изменения
истории Дневника. UI проверяется на реальном запущенном приложении, включая
длинный текст и управление подсказками с клавиатуры.
