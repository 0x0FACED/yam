# ADR 0020: Обязательный Онбординг При Первом Запуске

- Статус: принято
- Дата: 2026-09-25
- Область действия: запуск приложения и повторный онбординг из Настроек

## Контекст

Дневник сейчас открывается после интро даже тогда, когда пользователь ещё не
задавал цели. Цели сохраняются в `goal_versions`, но приложение загружает их
асинхронно: временное `SessionProfile == null` не означает первый запуск.

## Решение

- До выбора первого маршрута приложение различает загрузку локальной БД,
  отсутствие завершённого онбординга, завершённый онбординг и ошибку чтения.
  Признак прохождения — наличие хотя бы одной действующей записи `goal_versions`,
  которая атомарно сохраняется вместе с первым измерением веса. Отдельный
  persisted-флаг и миграция схемы не требуются; отсутствие веса после его
  удаления не сбрасывает прохождение.
- После интро при отсутствии целей открывается существующий трёхшаговый
  `/onboarding`. Пока он не завершён, основные экраны и task routes недоступны,
  в том числе через Back или прямую навигацию. На первом шаге нет закрытия;
  назад со следующих шагов можно перейти внутри формы. Неуспешное сохранение
  оставляет пользователя в форме и показывает локализованную ошибку.
- После успешного сохранения из обязательного онбординга открывается Дневник;
  при следующих запусках сразу открывается основное приложение. Повторное
  прохождение из Настроек подставляет сохранённые данные, допускает отмену и
  после сохранения возвращает в Настройки.
- Ошибка чтения БД не трактуется как новый пользователь: показывается
  локализованное состояние с действием повторной загрузки, не создающее
  дублирующий профиль и не открывающее Дневник без известного статуса.
- Интро и анимация раскрытия интерфейса остаются прежними и учитывают
  настройки доступности. Работает полностью локально без аккаунта и сети.

Этот ADR **заменяет** пункт ADR 0013 и ADR 0019 о запуске онбординга только из
Настроек и отказе от первого запуска. Остальные решения — три шага, поведение
при отмене повторного прохождения, независимые цели и session-only тема —
остаются в силе.

## Проверка

Проверяются пустая и уже заполненная БД, сохранение и повторный запуск,
невозможность обойти обязательный flow, повторный вход/отмена из Настроек и
повторная попытка чтения после ошибки. Обновление схемы и миграция не нужны.
