# ADR 0025: GitHub CI, Релизы И Версия Приложения

- Статус: принято
- Дата: 2026-10-22
- Область действия: GitHub Actions, Android signing, версия приложения и тесты

## Контекст

В репозитории нет GitHub CI/CD; публичная версия задана в `pubspec.yaml`,
но Settings/About содержат отдельную константу. Android release использует
debug signing. Пользователь запросил тесты на push, релизы по тегам и единое
версионирование; выбрал Android, Linux и macOS и постоянный Android-ключ
через GitHub Secrets. Удаление устаревших прототипных golden-тестов и PNG
согласовано отдельно; маскировать их ошибки или автоматически переснимать
эталоны в CI нельзя.

## Решение

### Проверки

- CI запускается на push во все ветки и на pull request, а также вызывается
  release workflow как обязательная проверка того же commit.
- Версия Flutter закреплена в `.fvmrc`; локальная разработка и Actions используют
  один SDK. Зависимости устанавливаются по `pubspec.lock` с enforce-lockfile;
  выполняются генерация l10n, статический анализ и весь `flutter test --coverage`.
- Устаревшие golden-тесты экранов прототипа и PNG удаляются, а не исключаются
  из discovery. Все оставшиеся проверки выполняются без skip/exclude-фильтров,
  continue-on-error и автоматического обновления эталонов. Поведенческие UI,
  расчётные, persistence и migration tests сохраняются.
- Actions закрепляются по проверенным commit SHA. Проверки и сборки имеют
  только read permissions; PR не получает signing secrets. Токен записи
  выдаётся только job публикации. Предыдущий CI ветки можно отменять; публикация
  релиза не прерывается новым запуском посередине загрузки файлов.

### Версия

- ADR 0005 остаётся источником правил SemVer. `pubspec.yaml` содержит единственную
  публичную версию `MAJOR.MINOR.PATCH+BUILD`, без ведущих нулей. Это также версия
  и номер локальной сборки.
- Релизный тег имеет вид `vMAJOR.MINOR.PATCH` и обязан совпадать с публичной
  версией `pubspec.yaml`. Несовпадающий или некорректный тег останавливает pipeline
  до платформенных сборок. Пререлизные суффиксы сейчас не вводятся в контракт
  native packaging.
- Release workflow переопределяет BUILD своим `github.run_number`; повторный
  запуск того же workflow сохраняет номер. Это конкретизирует разрешённый
  ADR 0005 CI override. Один проверенный номер, в пределах Android versionCode,
  и одно build name передаются всем трём сборкам. Счётчик workflow при будущем
  переносе/пересоздании нужно сохранить монотонным относительно выпущенных APK.
- `tool/release_metadata.dart` разбирает pubspec через YAML parser, проверяет
  тег/версию/номер и отдаёт одинаковые значения сборкам и именам артефактов.
  CI не переписывает pubspec, не коммитит bump и не создаёт теги автоматически.
- Settings и About показывают реальные package version/build number, прочитанные
  один раз при старте через `package_info_plus`, включая CI overrides.
  Версия передаётся приложению явно; в widgets нет I/O и запасной константы.
  `package_info_plus` 8.x сохраняет совместимость с текущими Flutter/toolchain
  и `file_picker`/win32 зависимостями. `yaml` становится прямой dev dependency
  для релизного инструмента.
- В Flutter 3.38.5 Linux asset `version.json` получает значения pubspec вместо
  CLI overrides: `tool_backend.dart` не передаёт BuildName/BuildNumber в assemble.
  Linux CMake устанавливает этот asset из уже корректных generated
  `FLUTTER_VERSION_*` через `linux/version.json.in`. Это исправляет native
  metadata на границе сборки, без запасной версии или special case в Dart.
  Перед упаковкой CI проверяет фактический Linux asset против версии релиза.

### Релиз

- Push тега `v*` запускает проверку метаданных, общие тесты и сборки Android APK,
  полного Linux x64 bundle и macOS app archive. iOS, Windows, магазины и Web
  в этот pipeline не входят.
- Android подписывается постоянным release keystore. Требуются Secrets:
  `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
  `ANDROID_KEY_PASSWORD`. При отсутствии секрета выпуск останавливается до
  платформенных сборок. Debug key fallback удаляется; debug-сборки по-прежнему
  не требуют release secrets. Приватный файл существует только во временном
  каталоге runner и удаляется после job, значения секретов не логируются.
- macOS архив без Apple Developer ID/notarization не выдаётся за подписанный
  магазинный релиз: Gatekeeper может требовать явного разрешения запуска.
  Упаковка сохраняет symlinks и permissions `.app`; архитектура указана честно
  в названии артефакта. Linux архив содержит весь bundle, а не только executable.
- GitHub Release публикуется только после успешных тестов и всех трёх сборок.
  Включаются SHA256SUMS. До завершения загрузки артефактов релиз остаётся draft,
  чтобы сбой загрузки не оставлял публичный неполный релиз.
- Настройка секретов выполняется владельцем репозитория. Агент не создаёт commit,
  теги, push, Secrets или публичные релизы; локальная проверка не подменяет
  фактический прогон GitHub-hosted runners.

## Последствия

Публичная версия меняется один раз в pubspec, затем владелец публикует совпадающий
тег. Новая release-подпись не обновит установленный APK с другим ключом; перед
возможной переустановкой нужно экспортировать `.yam`, чтобы не потерять историю.
Инструкции локальных проверок, создания ключа и настройки Secrets находятся
в README. После первого реального запуска Actions нужно проверить артефакты
на целевых ОС; локальные результаты и ограничения записываются в PROJECT_STATE.
