# ADR 0021: Поиск Open Food Facts И Локальный Кэш Выбранных Продуктов

- Статус: принято
- Дата: 2026-09-26
- Область действия: Food Search, внешний источник продуктов и SQLite

## Контекст

Экран поиска уже показывает локальные продукты, а записи Дневника содержат
неизменяемые снимки. Для поиска магазинных продуктов нужен необязательный
источник Open Food Facts (OFF), который не замедляет локальный ввод и не
смешивает внешние результаты с «Моими блюдами».

## Решение

- Три локальные вкладки сохраняются. При непустом запросе сначала отображаются
  локальные совпадения, ниже — отдельная секция `Open Food Facts` с собственными
  loading, empty, error и Retry. Поиск OFF начинается с трёх символов после
  debounce 650 мс; клиент ограничивает частоту до одного запроса в шесть секунд.
  Устаревшие ответы не меняют текущую выдачу. Отсутствие сети не блокирует
  локальный поиск, sheet или Дневник. При коротком запросе показывается
  пояснение о минимальной длине вместо окончательного «ничего не найдено».
- Для полнотекстового запроса используется Search-a-licious `GET /search`, а не
  `/api/v2/search`, который поддерживает только структурированные фильтры.
  Запрашиваются нужные поля и первая ограниченная страница; клиент передаёт
  идентифицирующий User-Agent. Данные OFF атрибутируются на экране поиска
  ссылками на источник и лицензию ODbL. Изображения не загружаются.
- В добавляемую выдачу попадают только продукты с кодом, названием и полными,
  конечными неотрицательными значениями ккал и БЖУ. Значения `_100g` остаются
  на 100 г; из размера упаковки или напитка не выводится порция и не
  предполагается равенство миллилитров граммам. Точность не округляется перед
  сохранением. В строке отображаются фактический бренд и локализованная
  категория; источник не выдаётся за бренд или отметку проверки.
- Только после добавления в Дневник или в Избранное OFF-продукт сохраняется в
  отдельной таблице SQLite. Первичный источник и его код задают устойчивую
  поисковую идентичность `off:<code>`; локальная запись имеет отдельный UUID v7,
  метаданные устройства и soft-delete поле. Повторное использование доступно
  без сети в локальном поиске, Recent и Избранном, но не в «Моих блюдах».
  Последнее выбранное количество в граммах запоминается для следующего sheet;
  при первом выборе предлагается 100 г.
  Повторный выбор актуального результата OFF может обновить кэш для будущих
  добавлений; старые diary snapshots не изменяются.
- Схема Drift обновляется аддитивно с v3 до v4: только новая таблица и её
  индексы, без смены имени файла, удаления или переписывания старых записей.
  Миграция проверяется на сохранённой схеме v3 с заполненными продуктами,
  порциями, Дневником, целями, весом и installation deviceId.

Это решение **заменяет** отсрочку удалённого поиска из ADR 0001 и текущего
scope в `agents/PROJECT_STATE.md`, а также ограничение ADR 0007 на fixture
search. Оно завершает переход к реальным локальным источникам, намеченный в
ADR 0012. Остальные правила ADR 0012 (три вкладки, цельная строка, отсутствие
выдуманных подборок, inline quick add и verified badge), flow ADR 0015 и
неизменяемые snapshots ADR 0018 сохраняются. Blueprint описывает объединение
выдачи как возможную архитектуру; для этого экрана отдельная секция важнее.

## Последствия

Пользователь может продолжать вести Дневник без доступа к OFF. Кэш является
источником только для будущего выбора продукта; сырые результаты запросов в
SQLite не записываются. Для Android release требуется INTERNET, для macOS —
разрешение исходящего соединения; UI атрибуции открывает внешние ссылки.

Документация OFF: https://openfoodfacts.github.io/openfoodfacts-server/api/ ;
https://search.openfoodfacts.org/docs ; https://world.openfoodfacts.org/data .
