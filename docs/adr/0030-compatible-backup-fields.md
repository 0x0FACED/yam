# ADR 0030: Совместимые Расширения Полей Резервных Копий

- Статус: принято
- Дата: 2026-10-26
- Область действия: `.yam`, импорт/экспорт начиная с текущей версии

## Контекст

Пользователю нужен обмен данными между версиями приложения, прежде всего
обновление существующей релизной БД и восстановление её старой резервной копии.
Строгое равенство JSON-ключей отклоняет даже добавление необязательного поля,
хотя текущая версия умеет безопасно восстановить все известные ей данные.

## Решение

- Экспорт остаётся `formatVersion: 2`; импорт поддерживает прежнюю v1 и v2.
  Версия SQLite не определяет версию переносимого формата.
- `formatVersion` обозначает несовместимое поколение формата, а не каждое новое
  поле. Добавление необязательных полей с безопасным значением по умолчанию
  не повышает её. Будущие совместимые экспортёры обязаны сохранять смысл,
  типы, единицы и обязательные поля существующего контракта.
- Неизвестные дополнительные JSON-поля записей и снимков порций игнорируются
  при чтении; дополнительные метаданные manifest/counts также не мешают импорту.
  Известные поля по-прежнему проверяются полностью: типы, конечность/диапазоны
  чисел, даты, UUID, уникальность, связи и согласованность дневниковых снимков.
  Неизвестное поле не заменяет отсутствующее обязательное.
- Nullable текстовые поля (`description`, `brand`, `barcode`, `label`) и
  nullable `deletedAt` могут отсутствовать: отсутствие означает null. Если
  поле присутствует, его значение обязано иметь корректный тип. Новое
  обязательное поле должно иметь явную миграцию/безопасное значение для старых
  копий либо потребует нового несовместимого поколения формата.
- Неизвестные поля не становятся новыми колонками SQLite и не хранятся в
  отдельном opaque-кэше. Старая версия переносит понятную ей часть данных;
  сведения, которых она не умеет хранить, могут исчезнуть при её повторном
  экспорте. Совместимость не означает lossless roundtrip неизвестных сущностей.
- Неизвестная версия формата, неизвестная единица/тип сущности в известном
  обязательном поле, другой состав ZIP, отсутствующий обязательный файл,
  повреждённый архив или превышение лимита по-прежнему отклоняются до записи.
  Новые сущности/изменение архивной структуры требуют отдельного решения;
  автоматического принятия любого будущего формата нет.
- Экспорт содержит все известные текущей версии поля. Режимы «Заменить» и
  «Дополнить», транзакционность, tombstones, ID установки и лимиты ZIP не меняются.
- Уже выпущенный старый бинарник с жёсткой проверкой ключей этим изменением
  не исправляется. Совместимость расширений действует начиная с данной версии;
  импорт существующих релизных `.yam` v1 сохраняется. Raw SQLite обновляется
  миграцией при обычном запуске и не выдаётся за файл импорта `.yam`.

Этот ADR **заменяет** строгую проверку точного состава JSON-полей и запрет
пропущенного nullable description в ADR 0024/0028. Выбор v2 для новых полных
копий, чтение v1 и остальные требования этих ADR сохраняются.

## Проверка

Реальная SQLite: дополнительные поля во всех шести таблицах и снимках порций,
nullable defaults, отсутствие обязательных полей, неправильные типы и будущая
несовместимая версия; оба режима импорта и повторный экспорт известных данных.
Отдельный runtime на приватных копиях существующей schema v4/backup v1 проверяет
миграцию и восстановление без изменения исходных файлов. Персональные данные
не попадают в тестовые fixtures, документацию или вывод проверки.
