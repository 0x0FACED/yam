# ADR 0029: Статусы Калорий В Недельном Календаре Дневника

- Статус: принято
- Дата: 2026-10-26
- Область действия: верхняя недельная строка Дневника и общая классификация дней

## Контекст

Пользователь хочет непосредственно в Дневнике видеть, какие дни отмечены едой
и какие укладывались в норму калорий, без перехода в Статистику. Статистика уже
определяет эти состояния по точному потреблению и исторической цели.

## Решение

- Семь дней отображаемой недели получают статусы из реальных локальных записей
  питания и версий целей. Расчёт общий со Статистикой по ADR 0019: 90–110%
  включительно — в цели, ниже 90% — недобор, выше 110% — превышение.
  Используется цель, действовавшая в соответствующий локальный день, а не
  сегодняшняя цель и не округлённое число ккал из UI.
- Цвета берутся из существующих семантических токенов: `goalWithin` (зелёный),
  `goalAbove` (жёлтый), `goalBelow` (цвет недобора). День с едой, но без цели,
  имеет нейтральную отметку; день без еды не окрашивается как недобор и не
  получает отметку затреканного дня. Нулевые ккал сохранённой еды — реальная
  запись, а не отсутствие записи.
- Выбранная дата и сегодняшний день остаются независимо различимы. Подсветка
  статуса не меняет выбор даты, геометрию календаря и доступные области нажатия.
  Значение статуса доступно в семантической подписи дня, не только цветом.
- Агрегация питания ограничена отображаемой неделей. Потоки локальной БД
  обновляют календарь при добавлении, правке, удалении/Undo еды и изменении
  целей. При переходе на другую неделю подписка меняет диапазон; устаревшие
  события не окрашивают новую неделю. Запросы и расчёты не запускаются из build.
- Хранить производные статусы в отдельной таблице не нужно. Схема БД и
  формат backup ради календаря не меняются. Поведение смены суток/возврата
  из фона не расширяется в рамках этой задачи.

Этот ADR дополняет ADR 0011 и 0019; правила навигации, текущего дня и
исторических целей сохраняются.

## Проверка

Границы 90/110%, историческая смена цели, отсутствие цели/еды и нулевые ккал;
диапазон недели при переходе месяца/года; реактивные изменения питания и Undo.
Ручная проверка запущенного календаря в Light/Dark, выбранной даты и отметки
сегодня; локализованные подписи состояний.
