# ADR 0042: Вставка Фото Из Буфера В Помощник

- Статус: принято
- Дата: 2026-11-06
- Основание: пользователь запросил обычную вставку фото без выбора файла на диске.

## Решение

- В поле чата обычная команда Paste (Cmd+V/Ctrl+V и контекстное меню) умеет
  прикреплять изображение из системного буфера. При отсутствии изображения
  сохраняется штатная вставка текста, включая выделение и undo.
- Изображение попадает в существующий предпросмотр. Вставка не отправляет запрос;
  отправка выполняется прежней кнопкой Send. Нет выбора файла, загрузки URL
  и записи в Дневник при вставке; YAM не сохраняет постоянную копию вложения.
- Используем `pasteboard ^0.5.0`: native clipboard для поддерживаемых платформ,
  без WebView/Rust runtime и собственных дублирующихся platform channels. Версия
  0.6 требует Flutter 3.44/Dart 3.12 и не подходит текущему SDK проекта.
  Native Windows backend пакета возвращает краткоживущий PNG из системной temp-
  директории и удаляет его после чтения; на macOS/Linux/iOS/Android — байты в памяти.
- Нативное чтение остаётся внутри assistant media service. Clipboard читается
  только по явной команде Paste, не при build/focus/таймере. Фото проходит тот же
  bounded decode, удаление EXIF/GPS и нормализацию, что фото из picker (ADR 0037).
- При смешанном clipboard изображение имеет приоритет над текстовым представлением.
  Сохраняется одно вложение, как в существующем UI. Ошибка подготовки не удаляет
  ранее введённый текст или прикреплённое фото. Остальные поля YAM не меняют Paste.

## Проверка

- Native clipboard → реальная команда Paste → предпросмотр, без автоматической
  отправки; удаление вложения и явная отправка.
- Текстовый clipboard: замена выделения, caret и undo; Paste из контекстного меню.
- Пустой/неподходящий clipboard, слишком большие данные, закрытие экрана во время
  обработки; изображение не попадает в историю, логи или постоянные файлы YAM.
