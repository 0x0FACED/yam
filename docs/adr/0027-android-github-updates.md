# ADR 0027: Обновления Android Из GitHub Releases

- Статус: принято
- Дата: 2026-10-23
- Область действия: Android, Настройки, публичные GitHub Releases

## Контекст

Пользователь запросил проверку обновлений, загрузку APK с прогрессом,
предложение установки и автоматическое удаление скачанного файла после
обновления. Владелец самостоятельно сделает `0x0FACED/yam` публичным;
распространение из приватного репозитория и GitHub-авторизация в приложении
не входят в решение.

## Решение

- В Android-Настройках появляется секция обновлений. Проверка выполняется
  при первом открытии секции в текущем запуске и повторно по кнопке.
  Старт приложения и локальная работа не ждут сеть. Скачивание и установка
  запускаются только пользователем.
- Источник — опубликованный стабильный `/repos/0x0FACED/yam/releases/latest`
  через публичный GitHub REST API. В приложении нет токенов. Приватный
  репозиторий, отсутствие релиза, сбои сети и ограничения API отображаются
  как ошибки проверки, а не как ложное «обновлений нет».
- Сохраняется контракт ADR 0025: `vMAJOR.MINOR.PATCH`, Android-артефакт
  `yam-MAJOR.MINOR.PATCH+BUILD-android.apk` и `SHA256SUMS` одного релиза.
  Обновление требует не меньшей публичной версии и строго большего Android
  versionCode; большая версия с меньшим versionCode не устанавливается.
- HTTP и разбор метаданных находятся вне widgets. APK скачивается потоком
  в приватный каталог приложения, без разрешения на общую файловую систему.
  Неполный файл имеет суффикс `.part` и не передаётся установщику. Длина и
  SHA-256 проверяются до предложения установки. `crypto` становится прямой
  Dart-зависимостью для потокового SHA-256; `androidx.core:core:1.16.0` —
  прямой Android-зависимостью для ограниченного FileProvider.
- Перед установкой Android проверяет идентификатор пакета, ожидаемые
  versionName/versionCode, увеличение versionCode и совместимость подписи
  с установленным приложением. SHA-256 обнаруживает повреждение загрузки;
  доверие обновлению обеспечивается также подписью APK, не одним checksum.
- Установка идёт через системный установщик и ограниченный content URI.
  Требуется подтверждение пользователя; при необходимости открываются
  системные настройки разрешения установки из этого источника. Тихая
  установка и обход Android-проверок не поддерживаются.
- APK нельзя удалять сразу после передачи установщику: пользователь может
  отменить установку, а система ещё читает файл. Целевая версия установки
  сохраняется отдельно от пользовательской БД. После `MY_PACKAGE_REPLACED`
  и при запуске новой версии удаляются ставшие ненужными установочные файлы;
  отмена установки не считается успешным обновлением.
- UI использует существующие семантические токены и YAM-компоненты, все
  пользовательские строки доступны на русском и английском. На iOS,
  macOS и Linux эта Android-секция не отображается; их дистрибуция по
  ADR 0025 остаётся прежней.
- Схема SQLite, резервные копии и история питания не меняются. Публичность
  репозитория, ключ подписи, коммиты, теги и публикации остаются действиями
  владельца; агент их не выполняет.

## Последствия

Первое приложение с этой функцией нужно установить обычным способом.
Дальнейшие APK должны иметь ту же release-подпись и больший versionCode.
Debug-установка не обновляется APK с другим release-ключом. Для настоящей
проверки GitHub нужны публичный репозиторий и опубликованный полный релиз.
