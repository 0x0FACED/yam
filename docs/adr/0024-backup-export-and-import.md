# ADR 0024: Экспорт И Импорт Резервных Копий

- Статус: принято
- Дата: 2026-10-22
- Область действия: перенос локальных данных, Настройки, файловые диалоги

## Контекст

История питания, собственные продукты, вес и цели уже сохраняются в SQLite,
но пользователь не может сделать резервную копию или перенести её на другую
установку. Пользователь поставил экспорт/импорт выше следующего функционального
среза и потребовал предлагать при импорте оба режима: заменить или дополнить.

## Решение

- Официальная резервная копия — файл `.yam`: ZIP с `manifest.json` и массивами
  записей в `user_foods.json`, `user_servings.json`, `diary_entries.json`,
  `goal_versions.json`, `weight_entries.json`, `remote_foods.json`.
  Manifest содержит `format: yam-backup`, `formatVersion: 1`, UTC `exportedAt`,
  `sourceDeviceId` и количества строк. Версия формата независима от SQLite v4.
  Сырой файл SQLite не является форматом обмена. Это конкретизирует пример
  `.foodtrack` из разделов 36–37 blueprint, не добавляя sync.
- Копия включает все строки UserFoods, UserServings, DiaryEntries, GoalVersions,
  WeightEntries и RemoteFoods: точные числа, дневниковые снимки, избранное,
  последнее количество OFF, UUID, метаданные и tombstones. Сессионные настройки
  и сессионное избранное встроенных продуктов в БД отсутствуют и не выдаются за
  сохраняемые данные. Схема SQLite не меняется.
- Экспорт читает согласованный снимок одной транзакцией. Кодирование,
  декодирование и сжатие выполняются вне UI isolate. Для ZIP используется
  `archive`; для системного выбора/сохранения файла — `file_picker` за небольшой
  границей файлового сервиса. Новые зависимости имеют конкретную задачу и не
  используются из бизнес-логики. Выбран `file_picker` 10.3.x: он сохраняет текущий
  iOS target 13, в отличие от 13.x с требованием iOS 14. macOS sandbox получает
  разрешение на чтение и запись выбранных пользователем файлов.
- Импорт сначала полностью проверяет структуру, версию, размеры, типы, числа,
  даты, идентификаторы, уникальность и связи. Файлы не распаковываются по
  произвольным путям. Повреждённый, неподдерживаемый или слишком большой файл
  отклоняется до изменения базы. Применение — одна транзакция с rollback.
  Ограничения v1: 64 MiB файла, 128 MiB распакованных данных, 250 000 записей
  и manifest не более 64 KiB. Обычный ZIP stored/deflate; шифрование, ZIP64,
  многотомность и data descriptors не поддерживаются. Метаданные читает
  `archive`, распаковка ограничена по объёму и проверяет CRC.
- Режим **Заменить** заменяет содержимое всех шести таблиц данными файла,
  включая удалённые строки. До записи показываются дата и состав копии,
  последствия и отдельное явное подтверждение замены. Пустая копия допустима;
  если после восстановления нет целей, приложение открывает обязательный
  онбординг.
- Режим **Дополнить** добавляет только отсутствующие ID, не изменяя существующие
  строки, в том числе tombstones. Это не last-write-wins и не синхронизация.
  При занятом штрихкоде или ID любой порции пропускается импортируемый
  пользовательский продукт со всеми его порциями; при занятой паре
  source+sourceCode — внешний продукт. Порции добавляются только вместе с новым
  продуктом: их нельзя присоединять к уже изменённому продукту другой базы.
  Дневниковые снимки независимы от каталога.
  Совпадения/конфликты учитываются в числе пропущенных записей; повторное
  дополнение той же копией не создаёт дубликаты.
- Device ID текущей установки не заменяется. В manifest сохраняется ID
  источника, а у импортируемых сущностей — исходные ID и метаданные. Новые
  изменения принадлежат установке-получателю.
- Настройки получают рабочие действия экспорта и импорта. В обязательном
  первом онбординге доступно то же восстановление из копии: для переноса
  истории не требуется сначала вводить фиктивный профиль. Отмена выбора файла
  или подтверждения ничего не меняет. На время операции исключаются повторные
  нажатия; ошибки и результат локализованы на RU/EN. После успешного импорта
  приложение перечитывает профиль и сбрасывает старое состояние экранов/Undo.
- Копия не зашифрована и содержит личные данные; UI сообщает об этом. Шифрование,
  фоновые автоматические копии и облачные интеграции в эту задачу не входят.

Это решение заменяет presentation-only ограничения ADR 0009 в части
экспорта/импорта. Остальные настройки и удаление всех данных не расширяются.

## Проверка

Реальная SQLite: полный roundtrip и точность, сохранность исторических снимков,
замена, дополнение, повторный импорт, конфликты естественных ключей, tombstones,
ID установки, отклонение некорректных/будущих файлов без потери текущих данных.
Отдельный runtime smoke проходит экспорт и оба варианта импорта через реальные
экраны с изолированными данными; системные диалоги проверяются там, где доступна
целевая платформа. Результаты и ограничения записываются в PROJECT_STATE.
