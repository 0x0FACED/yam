# ADR 0043: Локальная История Чатов Помощника

- Статус: принято
- Дата: 2026-11-06
- Основание: пользователь запросил сохранение чатов для истории и дополнительного контекста без обязательной оплаты старой переписки при каждом API-запросе.

## Решение

- Этот ADR заменяет session-only хранение переписки в ADR 0037/0039/0040. Текст отправленных сообщений и завершённых ответов сохраняется локально в SQLite; новый диалог не удаляет старый. История доступна без подключения к провайдеру.
- Отдельная таблица диалогов, schema v8: UUID v7, локальная дата/приём пищи, creation/update/device metadata, soft deletion. Полный `.yam` backup переносит текстовые диалоги; пищевой JSON их не содержит. Старые backup остаются совместимыми.
- Для `.yam` сохраняется formatVersion 3: необязательный известный файл `assistant_conversations.json` и его counts; отсутствие означает пустой архив. Этот ADR заменяет ограничение состава ZIP в ADR 0030 только для этого файла. Произвольные дополнительные файлы по-прежнему запрещены. Совместимость означает чтение старых копий новым приложением, а не чтение нового ZIP уже выпущенным старым бинарником.
- История открывается из AppBar помощника: ленивый список с названием из первого сообщения, датой изменения, выбором и подтверждаемым удалением. Новый диалог — отдельное действие. Композиция существующего чата, canonical tokens и ручное подтверждение еды не меняются; отдельного HTML-макета нет.
- Сохраняются только текст и отметка о приложенном фото. Фото, аудио, credentials, Responses payload, reasoning, tool calls и незавершённые черновики не входят в архив/backup. Восстановленное фото отображается как отметка, повторная отправка байтов невозможна. Удаление очищает текст в tombstone.
- Сначала сохраняется пользовательское сообщение, затем выполняется запрос. Ошибка локальной записи явно показана и не маскируется успешной отправкой. Завершённый ответ сохраняется до окончания операции; потоковые фрагменты не считаются ответом.
- Возврат к чату восстанавливает текст и выбранную дату/приём, но не разрешения старых инструментов и не черновик. Подтверждённые записи не воспроизводятся. Действие подтверждения/отклонения отражается текстовой отметкой в истории, чтобы архив не создавал впечатление несохранённого черновика.
- Сохранённая переписка по умолчанию не отправляется модели. В открытом архивном чате есть явный переключатель контекста: максимум последние 12 сообщений и 12 000 символов текста на следующий запрос. Фото, tools и прочие чаты туда не входят. После успешного запроса переключатель сбрасывается; новый текущий обмен сохраняет обычный сессионный API-контекст. Это не скрытая автоматическая память и не бессрочная пересылка всех чатов.
- Закрытие/смена диалога предупреждает только о несохранённом вводе, медиа, черновике или выполняющемся запросе; сохранённый текст не требует подтверждения потери. При смене подключения начинается новая сессия API без старого протокольного контекста.

## Проверка

- Перезапуск хранилища и контроллера: порядок/точный текст/дата, отсутствие фото и tool payload, новый диалог не уничтожает старый, удалённый не появляется снова.
- Миграция старой БД сохраняет дневник; backup переносит историю, старый формат остаётся читаемым.
- Запрос без переключателя не содержит архив; включённый контекст ограничен и не повторяет инструментальные команды. Ошибка/отмена не сохраняют незавершённый ответ.
- Реальный native Flutter UI: список, открытие, новый чат, удаление и восстановление после перезапуска с изолированной БД; format/analyze и фокусные persistence/controller проверки.
