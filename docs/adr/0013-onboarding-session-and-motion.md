# ADR 0013: Онбординг В Памяти И Появление Интерфейса

- Статус: принято
- Дата: 2026-09-23
- Область действия: визуальный прототип, до persisted user profile

## Контекст

Три эталонных экрана описывают выбор цели, ввод веса и суточные цели питания.
Реального сохранения пользовательских настроек пока нет, а интро сразу
показывает Дневник. Резкое появление контента после интро делает интерфейс
визуально тяжёлым.

## Решение

- Онбординг запускается по отдельному действию в Настройках и не навязывается
  при каждом запуске приложения. Порядок шагов: цель (`yam_onboarding_1.html`),
  вес (`yam_onboarding_3.html`), цели питания (`yam_onboarding_2.html`).
- При первом запуске формы поля заполнены демонстрационными значениями из
  экранов: 74,2 / 72 кг, 1950 ккал, 140 / 65 / 210 г. Пользователь может
  изменить значения. Повторный запуск формы подставляет значения текущей сессии.
- Переходы вперёд и назад выполняются кнопками с коротким горизонтальным
  перелистыванием. Свайп между шагами отключён; состояние полей не теряется.
  Переход вперёд требует корректных чисел, а кнопка завершения применяет данные.
- Завершение возвращает пользователя в Настройки. Цели сразу отражаются в
  Настройках и Дневнике, вес — в Настройках. Данные живут только в памяти
  текущего запуска; отмена онбординга не перезаписывает предыдущие значения.
- После интро и завершения онбординга экран проявляется слоями: сначала каркас,
  затем видимые смысловые блоки через непрозрачность без смещения или масштаба.
  Анимация короткая, не повторяется при обычной перестройке и отключается при
  `MediaQuery.disableAnimations`.
- Переиспользуемые поля, карточки выбора, прогресс шагов и reveal-анимация
  живут в `lib/core/ui`, значения движения — в `lib/app/theme/app_motion.dart`.

Это решение уточняет текущий статус онбординга в `agents/PROJECT_STATE.md`:
отдельный маршрут реализуется сейчас, без изменения cold-start до появления
настоящего persisted state. Расширенный опрос и автоматический расчёт целей
из старых разделов blueprint остаются заменёнными ADR 0002.

## Последствия

При подключении persistence session model будет заменена источником истины,
не меняя формы и её визуальный контракт. Значения демо-дня питания остаются
снимками и не пересчитываются при изменении цели.
