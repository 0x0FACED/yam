# База Продуктов YAM: JSON

В **Настройки → База продуктов** можно экспортировать «Мои блюда» или
импортировать продукты из обычного `.json`-файла в UTF-8. В приложении есть
описание формата и кнопка копирования минимального примера.

Это обмен продуктами, **не резервная копия приложения**. Дневник, вес, цели,
профиль, встроенные продукты и сохранённые Open Food Facts в файл не входят.
Для переноса всей истории используйте отдельные действия полного backup `.yam`.

## Минимальный Файл

Скопируйте пример в `foods.json`. Добавляйте объекты в массив `foods`, разделяя
их запятыми. JSON не допускает комментариев и запятых после последнего элемента.

```json
{
  "format": "yam-foods",
  "version": 1,
  "foods": [
    {
      "name": "Творог 5%",
      "category": "Молочные продукты",
      "unit": "g",
      "basisAmount": 100,
      "kcal": 121,
      "protein": 17,
      "fat": 5,
      "carbs": 2
    }
  ]
}
```

## Поля Продукта

| Поле | Обязательно | Значение |
| --- | --- | --- |
| `name` | Да | Непустое название |
| `category` | Да | Непустая категория, свободный текст |
| `unit` | Да | `g` — граммы, `ml` — миллилитры |
| `basisAmount` | Да | Положительное количество г/мл, на которое указано КБЖУ |
| `kcal` | Да | Килокалории на `basisAmount` |
| `protein`, `fat`, `carbs` | Да | Граммы БЖУ на `basisAmount` |
| `brand` | Нет | Бренд, строка или `null` |
| `barcode` | Нет | Строка цифр, не число: так сохраняются ведущие нули |
| `description` | Нет | Описание, например состав/приготовление; переносы строк — `\n` |
| `displayBasis` | Нет | `per100` или `perServing`, см. ниже |
| `servings` | Нет | Массив дополнительных порций |

Числа записываются **без кавычек**, десятичный разделитель — **точка**.
КБЖУ должно быть конечным и неотрицательным. Калории сохраняются как указано,
не пересчитываются из БЖУ и не округляются перед записью. Ручная форма YAM
по-прежнему рассчитывает калории из БЖУ при создании/сохранении продукта.
Миллилитры не приравниваются к граммам.

Если `displayBasis` отсутствует, `basisAmount: 100` означает показ на 100 г/мл,
другой базис — на порцию. `per100` требует `basisAmount: 100`.
`perServing` позволяет явно выбрать показ на порцию, в том числе в 100 г/мл;
недостающая порция с таким эквивалентом создаётся автоматически.

Необязательные поля можно не указывать; nullable-поля могут быть `null`.
`servings` можно опустить или передать пустым массивом. Неизвестные
дополнительные поля игнорируются и не сохраняются. Другие версии формата
отклоняются: версия JSON не связана с версией SQLite или backup `.yam`.

## Порции И Описание

```json
{
  "format": "yam-foods",
  "version": 1,
  "foods": [
    {
      "name": "Домашний суп",
      "category": "Супы",
      "description": "Состав: овощи, курица, вода.\nВыход: 4 порции по 300 г.",
      "unit": "g",
      "basisAmount": 300,
      "displayBasis": "perServing",
      "kcal": 210.5,
      "protein": 18.25,
      "fat": 6.5,
      "carbs": 19.75,
      "servings": [
        {
          "unit": "serving",
          "label": "Тарелка",
          "baseAmount": 300,
          "defaultAmount": 1
        }
      ]
    }
  ]
}
```

Это пример структуры, а не проверенный рецепт или справочные КБЖУ.

Поля порции:

- `unit`: `serving` (порция), `piece` (штука), `glass` (стакан), `scoop` (мерная ложка);
- `baseAmount`: положительное количество г/мл **в одной такой единице**;
- `defaultAmount`: положительное число единиц по умолчанию, при отсутствии — 1;
- `label`: необязательное название порции.

Если базис продукта — `ml`, все его `baseAmount` также в мл. Например,
стакан 250 мл — `{"unit":"glass","baseAmount":250}` при `unit: "ml"`
у самого продукта. Сведения о плотности из файла не выводятся.

## Три Режима Импорта

1. **Заменить базу продуктов.** Текущие «Мои блюда» и их порции убираются;
   добавляются все записи файла, включая повторы. Требуется отдельное
   подтверждение. `"foods": []` очищает «Мои блюда».
2. **Объединить без дублей.** Существующие записи не меняются. Совпадение —
   одинаковые название и бренд без учёта регистра, крайних и повторных пробелов,
   единица, базовое количество и все четыре значения КБЖУ. Сравнение чисел точное,
   без округления; 50 г и 100 г не объединяются даже при пропорциональном составе.
   Проверяются и текущая база, и повторы внутри файла: сохраняется первая запись.
   Пустой и отсутствующий бренд равны. Категория, описание, штрихкод и порции
   в ключ не входят; у совпадения сохраняются все поля существующего продукта.
   Ранее существовавшие дубли этот режим не удаляет.
3. **Объединить с дублями.** Каждая запись становится новым продуктом.
   Повторный импорт того же файла добавляет ещё одну копию всех записей,
   в том числе с одинаковыми штрихкодами.

Все добавленные продукты доступны для правки в «Моих блюдах», как созданные
вручную. История дневника во всех режимах сохраняет свои прежние имена/КБЖУ.
UUID, deviceId и даты создавать в JSON не нужно: их назначает YAM.

Файл полностью проверяется **до изменения базы**. При ошибке не импортируется
ничего; для некорректного поля показывается JSON-путь, например `foods[2].kcal`.
Отмена выбора файла или подтверждения не меняет данные. Лимиты: 64 МиБ,
50 000 продуктов, 250 000 порций (включая автоматически созданные).

## Запрос К ИИ

Можно передать ИИ минимальный пример и такое требование:

> Создай только валидный JSON без Markdown и комментариев: format "yam-foods",
> version 1, массив foods. У каждого продукта нужны name, category, unit (g/ml),
> basisAmount, kcal, protein, fat, carbs. КБЖУ должно относиться к указанному
> basisAmount. Числа без кавычек, с десятичной точкой. Не выдумывай отсутствующие
> пищевые значения: перечисли недостающие сведения отдельно, до создания файла.
> Бренд, штрихкод-строка, описание и порции необязательны. Не добавляй дневник,
> персональные данные, UUID и служебные даты.

YAM проверяет структуру и допустимость чисел, **не достоверность пищевого
состава**. Проверяйте значения по упаковке или надёжному источнику.

Решение и границы: [ADR 0034](adr/0034-food-library-json-import-export.md).
